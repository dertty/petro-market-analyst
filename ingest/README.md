# Сбор корпуса отраслевых отчётов

Собирает файлы отчётов (OPEC, EIA, JODI, World Bank, санкционные первоисточники и т. д.) в
`data/corpus/` для будущего RAG. Эта итерация — только сбор файлов: без извлечения текста,
без индекса, без подключения к агенту. Полный контекст и решения — в дизайн-плане сессии,
которым собран этот каталог (см. git log).

Запускается на хосте (`python -m ingest.<модуль>`), не в контейнере: `data/` живёт на
хосте, а тянуть эти зависимости в образ веб-приложения незачем.

## Установка

```bash
pip install -r ingest/requirements.txt
```

## Как запускать

```bash
# Разведка достижимости — какие источники вообще отвечают, без единой загрузки файла
python -m ingest.probe
python -m ingest.probe --only OPEC-001 EIA-001

# Сбор
python -m ingest.collect --dry-run              # план: что будет скачано, без загрузки
python -m ingest.collect                         # все source со status: collect (24 шт.)
python -m ingest.collect --only EIA-001 EIA-002   # только перечисленные

# Файлы, которые пользователь положил руками в data/corpus/uploads/
python -m ingest.uploads
```

Повторный запуск `collect` идемпотентен: для детерминированных стратегий
(date_pattern/listing/feed) уже собранные edition_key не перекачиваются вообще — проверка
по `doc_id` в манифесте, без единого HTTP-запроса. Для `single` документ скачивается заново
и сравнивается по sha256; при совпадении файл на диске не остаётся и манифест не
пополняется.

## Структура

```text
data/corpus/
  raw/<publisher_slug>/<series_slug>/<doc_id>.<ext>   автосбор
  uploads/                                             файлы пользователя, как положил
  manifest.jsonl                                       единственный вход для будущего индексатора
  probe-report.json                                    последний отчёт разведки достижимости
```

Подробности именования, doc_id и схемы манифеста — в дизайн-плане; здесь только
эксплуатационные команды.

### Известное поведение WPSR (EIA-002)

`date_pattern` для WPSR предполагает «каждую среду» — подтверждено при разведке, но не
абсолютно: в недели с праздниками США EIA иногда сдвигает релиз на четверг, и `date_pattern`
это пропускает (404 на среду). При первом полном сборе (2026-08-09) так пропущено 15 из 104
недель за 24 месяца — каждая видна в выводе `collect.py` как `FAILED`, ничего не молчит.
Не патчим календарём праздников: 89/104 — рабочий результат для календарного шаблона, а
особый код ради 15 сдвинутых на день недель — заметно больше сложности, чем эффект.

## Как добавить источник

1. Добавить запись в `ingest/registry.yaml` с `status: collect`, `strategy` (см. ниже) и
   всеми обязательными полями — по образцу соседних записей.
2. Прогнать `python -m ingest.probe --only <ID>` — источник должен отвечать 2xx до того,
   как под него настраивается стратегия.
3. Прогнать `python -m ingest.collect --only <ID> --dry-run` и проверить, что кандидаты
   выглядят разумно (правильные edition_key, правильные URL).
4. Прогнать без `--dry-run`, проверить файлы в `data/corpus/raw/` и строки в манифесте.

### Стратегии (`ingest/strategies.py`)

- **date_pattern** — URL выводится из календаря по шаблону (`params.url` с `{d:...}`).
  Использовать только когда шаблон подтверждён явной проверкой архива издателя (curl/
  WebFetch), а не угадан по аналогии с другим изданием того же издателя.
- **listing** — GET `params.landing`, ссылки на файлы (pdf/xlsx/xls/csv/doc/docx) на
  странице, дата — из URL, видимого текста ссылки или атрибута `title`. Best-effort:
  работает только там, где издатель ссылается на файлы напрямую со страницы-списка.
- **feed** — то же самое, но без ограничения на N последних — берёт всё в окне
  `depth.months`. Годится для лент событий, где каждый пункт — отдельный файл/PDF.
- **single** — один текущий документ, история — по изменению sha256.

## Что делать при отказе источника

Отказ источника — громкая ошибка (`collect.py` печатает его в разделе "нужно чинить" или
"часть выпусков не скачалась"), а не молчаливый пропуск. Прежде чем чинить:

1. **`FAILED: стратегия не нашла ни одного выпуска`** — генерик-парсер `listing`/`feed`
   ищет только прямые ссылки на файлы (`<a href="....pdf">` и т.п.) в статичном HTML.
   Не находит ничего, если издатель:
   - рендерит ссылки через JS (нужен headless-браузер — вне scope этой итерации);
   - ссылается на HTML-страницы отдельных материалов, а не на файлы напрямую;
   - убрал файловый формат вовсе (пример: EIA Petroleum Supply Monthly — PDF/CSV
     официально прекращены).
   Список источников с этой проблемой и разбор по каждому — в `PROBLEMS.md` в корне
   проекта. Это НЕ повод писать под конкретный сайт хрупкий парсер по одному селектору —
   если паттерн общий (например, дата в `title`, а не в тексте ссылки — как оказалось у
   EIA Monthly Energy Review), чинится в `ingest/strategies.py`/`ingest/dates.py` один раз
   для всех источников, а не точечно.

2. **`403`/`402`/CDN-блокировка при разведке** — не подбирать обход (смена TLS-отпечатка,
   headless-браузер для прохождения challenge и т. п.). Перевести источник в
   `registry.yaml` на `status: skip, reason: blocked` с датой и деталями проверки в
   `note`. `landing` в записи сохраняется, чтобы решение было обратимо сменой `status`
   одним словом, если у издателя появится другой канал доступа.

3. **User-Agent блокируется по строке заголовка**, но обычный браузерный UA проходит
   (проверять через `curl -A "Mozilla/5.0 ..."`, не через `ingest.http`, чтобы исключить
   особенности TLS-стека httpx) — это не повод писать под каждый такой сайт свой UA:
   `ingest/http.py` уже использует стандартный браузерный User-Agent для всего движка
   (см. комментарий там же). Если и с ним не проходит — см. пункт 2.
