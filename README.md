# Нефтегазовый аналитик

Веб-интерфейс к агенту-аналитику нефтегазового рынка. Пользователь задаёт вопрос, агент
исследует открытые источники веб-поиском и возвращает разбор со ссылками.

Под капотом — [Ouroboros](https://github.com/razzant/ouroboros) как подмодуль. Приложение
общается с ним через task API и не даёт браузеру обращаться к рантайму напрямую.

## Запуск

```bash
git clone --recurse-submodules https://github.com/dertty/petro-market-analyst.git
cd petro-market-analyst
cp .env.example .env      # заполнить OPENROUTER_API_KEY
docker compose up --build
```

Интерфейс — <http://127.0.0.1:8000>. Первая сборка занимает около минуты.

Если репозиторий уже склонирован без подмодуля:

```bash
git submodule update --init --recursive
```

## Что где лежит

| Путь | Что это |
|---|---|
| `app/` | веб-приложение: FastAPI и одна HTML-страница |
| `knowledge/` | база знаний аналитика — под git, правится руками |
| `skills/` | свои скиллы, когда появятся |
| `vendor/ouroboros/` | подмодуль рантайма, закреплён на теге |
| `data/` | состояние рантайма, вне git, создаётся при первом старте |
| `PROBLEMS.md` | что решено компромиссно и что не решено |

## Ключи и настройки

Обязателен один ключ — `OPENROUTER_API_KEY`: модель по умолчанию и обе резервные это
идентификаторы каталога OpenRouter. Второй обязательный параметр, `OUROBOROS_RUNTIME_MODE=light`,
уже стоит в `.env.example`: по умолчанию рантайм работает в режиме `advanced`, где имеет право
писать в собственный репозиторий.

**Ловушка, из-за которой поведение разойдётся между машинами.** У Ouroboros есть свой
веб-интерфейс с настройками. Если сохранить ключ через него, значение запишется в
`data/settings.json` и начнёт **перекрывать** `.env`, а `data/` в git не попадает. Меняйте
ключи только в `.env`.

## Две вещи, которые сбивают с толку

**Папка `data/memory/knowledge` на хосте пустая.** Это точка монтирования: реальные файлы
лежат в `knowledge/` в корне проекта. Туда же смотреть при правках. То же для
`data/skills/external` и `skills/`.

**Рантайм виден на порту 8766, а не 8765.** Так сделано, чтобы не конфликтовать с нативной
установкой Ouroboros, если она работает на той же машине. Внутри сети Docker порт всегда 8765,
приложение от этого не зависит. Меняется через `OUROBOROS_HOST_PORT` в `.env`.

## Как это работает

Каждый вопрос — отдельная задача рантайма с собственным каталогом данных
(`memory_mode: "forked"`). Поэтому между вкладками и пользователями не течёт ни история, ни
память: у задачи пустой журнал переписки и своя копия базы знаний.

Историю сессии несёт приложение: идентификатор сессии живёт в `sessionStorage` браузера, и при
каждом новом вопросе предыдущие вопросы и ответы этой сессии подставляются в текст задачи.
Отсюда два следствия:

- **Перезагрузка страницы начинает новую сессию.** Прошлые ответы остаются в рантайме, но связь
  с ними теряется — это осознанный выбор в пользу изоляции.
- **Каждый следующий вопрос в сессии дороже предыдущего**, потому что история едет целиком.

## Правка базы знаний

`knowledge/` — обычные markdown-файлы под git. В контекст задачи попадает только
`index-full.md`; остальные топики агент читает сам, когда они нужны. Поэтому:

- новый топик — новый файл в `knowledge/`, **плоско**: вложенные каталоги в индекс не попадают;
- добавили топик — допишите строку про него в `index-full.md`, иначе агент о нём не узнает;
- правки подхватываются без пересборки образа, каталог смонтирован.

Инструмент записи знаний у задачи отключён намеренно: на своём каталоге задачи запись не попала
бы в общую базу, а инструмент отрапортовал бы успехом. База меняется только вами и только
через git.

## Безопасность

Аналитической задаче запрещено править код: снят большой список инструментов
(`app/ouroboros_client.py`, `DISABLED_TOOLS`) и объявлены защищёнными каталоги `skills`,
`vendor`, `app`. Python для расчётов при этом оставлен.

**При обновлении подмодуля список инструментов надо пересматривать.** Белого списка в контракте
задачи нет, только чёрный, а неизвестное имя молча ничего не отключает: новый инструмент записи
в новой версии Ouroboros ослабит защиту без единого признака.

Порт рантайма привязан к `127.0.0.1`. Выносить его в сеть без `OUROBOROS_NETWORK_PASSWORD`
нельзя: при пустом пароле проверка пропускает всех. У самого приложения аутентификации нет
вовсе — см. `PROBLEMS.md`.

## Обновление рантайма

```bash
cd vendor/ouroboros
git fetch managed --tags
git checkout <новый тег>
cd ../..
git add vendor/ouroboros && git commit -m "Ouroboros <новый тег>"
```

`origin` подмодуля — ваш форк (туда уходят коммиты), `managed` — оригинальный репозиторий
(оттуда приходят обновления).

Если после клонирования на Windows контейнерный git показывает весь `vendor/ouroboros`
изменённым, это перевод строк:

```bash
cd vendor/ouroboros
git config core.autocrlf false && git config core.eol lf
git rm --cached -r . && git reset --hard
```
