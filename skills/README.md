# Свои скиллы

Каталог монтируется в `/workspace/data/skills/external` — туда, где рантайм ищет скиллы
из внешнего бакета. Структура: `skills/<slug>/SKILL.md` с frontmatter и `plugin.py` с
`def register(api)`. Образец — `vendor/ouroboros/skills/unix_computer_use/`.

Перед включением скилл проходит автоматическую проверку и ревью моделями, включает его владелец.
Аналитическая задача сделать этого не может: `skill_review`, `skill_preflight` и `toggle_skill`
сняты в `app/ouroboros_client.py`, а сам каталог объявлен защищённым от записи.

Включение автоматизировано: сервис `skill-enable` в `docker compose` прогоняет
`scripts/enable_own_skills.py`, который обходит каталоги здесь и доводит каждый до
рабочего состояния (owner-аттестация плюс флаг «включено»). Разбор в `PROBLEMS.md`,
запись 24. Вручную то же самое:

```bash
docker compose run --rm skill-enable
```

**После правки файлов скилла его нужно включить заново** — правка меняет хеш содержимого,
и прежний вердикт ревью становится недействительным, а инструмент молча исчезает из
набора задачи.

Две грабли, на которые уже наступали: двоеточие в незакавыченном значении YAML
(`when_to_use: ... ПЕРЕД веб-поиском: ...`) ломает frontmatter целиком — для длинных
описаний нужен блочный скаляр `>-`; и `permissions` обязаны совпадать с тем, что
`plugin.py` реально вызывает, — preflight сверяет это статическим разбором кода.

## `oil_price_forecast`

Расчётный модуль прогнозирования цен на нефть: `forecast` (прогноз Brent/WTI на 1–12 месяцев
двумя методами с интервалом 80 %) и `supply_shock` (диапазон цен при изменении добычи через
эластичности). Подробности — в `oil_price_forecast/SKILL.md` и разделе README проекта.

Одна особенность, важная при добавлении следующих скиллов: расчётный стек стоит в образе
рантайма, а `dependencies` в манифесте намеренно **не объявлены**. Объявленные зависимости
переключают расширение в out-of-process-режим, где `register()` выполняется заново на каждый
вызов инструмента, — для скилла, держащего модель в памяти, это неприемлемо. Разбор в
`PROBLEMS.md`, запись 19.

## `petro_rag`

Поиск по загруженным PDF-отчётам: `rag_search` возвращает дословные фрагменты с готовой
ссылкой вида `[отчёт, дата, с. N]`. Индекс собирается офлайн (`scripts/build_index.py`)
и лежит в `reports/index/`; агент его только читает.

Отличается от соседа тем, что модели живут не в модульной глобали, а в
процессе-компаньоне: `multilingual-e5-large` весит около 2 ГБ, а расширение грузится в
сервер и в каждый из десяти воркеров. Для 50-мегабайтного Chronos in-process оправдан,
здесь — нет. Обоснование и замеры — в `petro_rag/SKILL.md` и `petro_rag/tests/README.md`.
