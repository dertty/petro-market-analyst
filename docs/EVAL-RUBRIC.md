# Рубрика оценки прогона: как считать две метрики качества

Файл нужен, чтобы оценка одного и того же прогона не менялась от раза к разу. Когда
поступает просьба «оцени прогон» — работать строго по этому файлу и по нему же
отчитываться. Любое решение, которого здесь нет, после вынесения дописывается в §6.

Парный документ — `EVAL-AGENT.md`: там датасет, семантика полей записи и определения
детерминированных проверок. Здесь — как из них собирается оценка.

Метрики две, обе по шкале 0–100 %, считаются по одному и тому же прогону независимо
друг от друга. Ни одна не заменяет другую: проверка протокола не читает содержание,
экспертная оценка не видит формальных нарушений.

## 1. Соответствие протоколу

Считается кодом по `checks` в `results.jsonl`, денег не стоит. Пересчитать проверки
для старого прогона: `python scripts/eval_run.py --rebuild eval_runs/<id>`
(нужен `PYTHONIOENCODING=utf-8`, иначе падает на печати кириллицы).

Проверки делятся по тому, что означает провал.

**Блокирующие — ответ нельзя отдать пользователю:**
`completed`, `citation_validity`, `fact_accuracy`, `forecast_protocol`, `refusal_no_tools`.

**Штрафные — ответ годен, нарушен процесс:**
`tool_choice`, `rag_before_web`, `web_budget`, `citation_format`, `structure`.

Балл ответа:

- любая блокирующая провалена → **0**, штрафные не считаются;
- иначе → доля пройденных штрафных среди применимых (нет применимых → 1,0).

Метрика прогона — среднее баллов по всем записям. Проверки со статусом `skip`
(не применимы к сценарию) в знаменатель не входят. Незавершённая запись получает 0,
а не исключается: прогон, где половина задач умерла, не должен выглядеть здоровым.
Если незавершённые есть — назвать их количество в тексте.

`structure` в `EVAL-AGENT.md` помечена как warning; здесь она считается штрафной
наравне с остальными — отдельный уровень «предупреждение» не нужен, вес и так в пять
раз меньше блокирующей.

## 2. Экспертная оценка

Оценка чтением, автоматизация не планируется. Источник критериев — поле
`judge_criteria` записи датасета (обычно два критерия), плюс `reference_answer`
и `expected_facts`, где они есть.

**Вердикт по критерию строго бинарный.** Половинных баллов нет: они и есть главный
источник расползания оценки. Если критерий выполнен частично — это провал, а
основание для смягчения выносится в §6 как правило присуждения, чтобы в следующий
раз дало тот же результат.

Метрика прогона = сумма пройденных критериев / сумма всех критериев.

**Что оценивается:** соответствие критерию и непротиворечие эталону.
**Что не оценивается:** стиль, длина, полнота сверх критерия, красота структуры,
согласие оценивающего с выводом агента.

## 3. Общие правила присуждения

1. **Числа против эталона.** Расхождение с `reference_answer` в числе или вероятности —
   провал критерия, ссылающегося на эталон. Дополнительные числа сверх эталона
   провалом не являются.
2. **Внешние данные.** Критерий «опирается только на отчёт» не нарушается привлечением
   внешних данных, если внешнее число помечено своим источником и либо вопрос без него
   не решается (например, «сбудется ли прогноз»), либо оно вынесено за пределы вывода
   и явно названо не отчётом. Нарушается — когда внешнее число подано как содержимое
   отчёта или противоречит эталону.
3. **Непроверяемый веб.** Число из веба без URL допустимо, если помечено как
   непроверяемое. Провал — когда такое число попадает в вывод как установленный факт
   без оговорки.
4. **Выход расчётного модуля.** Если вопрос прогнозный, итоговым числом ответа — тем,
   которым он закрывается, — должен быть выход модуля. Провал критерия о подаче
   прогноза — и когда собственный сценарный расчёт агента подменил выход модуля,
   и когда выход модуля приведён, но ответ закрывается другим диапазоном: читатель
   уносит именно закрывающее число.
   Оговорки на месте и приведённый интервал от провала не спасают.
5. **Перечисление возможностей.** Критерий, требующий назвать возможности (профильные
   вопросы, поиск по отчётам, прогноз цен), выполнен только при упоминании всех
   перечисленных в нём. Перечень тем отрасли возможностями не является.
6. **Артефакты цикла приёмки** (ответ начинается репликой ревьюеру: «Принято.
   Исправляю…», «Теперь финальный ответ…») в экспертную метрику не входят — ни один
   критерий их не описывает. Считать их отдельно и называть числом «ответов с
   артефактом N из M». Если реплика вытеснила ответ целиком — это провал всех
   критериев записи и `completed`-годного, но пустого ответа.
7. **Обоснование внутри критерия.** Часть формулировки критерия, объясняющая, зачем
   требование нужно («…и что у отчёта достоверность, у веба свежесть»), обязательной
   фразой в ответе не является. Проверяется требование, а не его пересказ.

## 4. Формат отчёта

Фиксированный, без добавочных строк:

| | \<прогон A\> | \<прогон B\> |
|---|---|---|
| Соответствие протоколу | | |
| Экспертная оценка | | |
| Латентность, среднее | | |
| Длина траектории, среднее (раунды) | | |
| Стоимость ответа, средняя | | |

Ниже — разбивка экспертной оценки по записям и перечень провалов с причинами.
Сравнивать прогоны допустимо только на одинаковом наборе вопросов.

## 6. Журнал решений

Дописывать сюда каждое новое решение, чтобы следующая оценка совпала с прошлой.

- **2026-08-10.** `rag-001`, критерий «опирается только на данные отчёта»: засчитан,
  хотя ответ привлекает EIA, STEO и FRED. Вопрос спрашивает вероятность реализации
  прогноза, из отчёта она невыводима; числа отчёта совпали с эталоном, внешние
  помечены. Основание — правило 2.
- **2026-08-10.** `hyb-001` на итерации 2: оценка «~$81 от SberCIB» получена из perplexity
  без URL, но ответ прямо пишет, что источник не проверяем и что мартовский документ
  этого числа не содержит. Критерии засчитаны. Основание — правило 3.
- **2026-08-10.** `oos-001`: 100 % по протоколу в обоих прогонах при 1/2 по экспертной оценке.
  Расхождение не ошибка метрик — механические проверки возможностей не проверяют.
- **2026-08-10, итерация 3.** `rag-001`, тот же критерий «опирается только на данные
  отчёта»: засчитан, хотя ответ приводит заявление топ-менеджмента Сбера из веба, а
  вопрос на этот раз решался из отчёта целиком. Уточнение правила 2: необходимость
  внешних данных — не единственное основание. Критерий не нарушается, если внешнее
  число вынесено за пределы вывода, помечено своим источником и явно названо не
  отчётом. Нарушение остаётся прежним: внешнее подано как содержимое отчёта или
  противоречит эталону.
- **2026-08-10, итерация 3.** `hyb-001`, критерий «…и что у отчёта достоверность,
  у веба свежесть»: эта часть формулировки читается как обоснование требования, а не
  как обязательная фраза в ответе. Критерий засчитывается, когда расхождение не
  усреднено и каждое число помечено как прогнозное или фактическое. Так был засчитан
  итерации 1, где той же фразы тоже не было.
- **2026-08-10, итерация 3.** `fc-001`: правило 4 срабатывает не только при подмене
  выхода модуля. Ответ привёл медиану и интервал модуля и назвал их центральной
  оценкой, но закрылся собственным диапазоном $70–90 «с тяготением к снижению» —
  читатель уносит именно его. Критерий о подаче прогноза провален.
- **2026-08-10, итерация 4.** `oos-002`, `oos-003`, `oos-004`, `oos-006`, критерий
  «предложена помощь по профильной теме»: перечисление своей специализации в ответ на
  непрофильный вопрос засчитывается. Явного приглашения («спрашивайте», «сформулируйте
  вопрос») критерий не требует — назвать, о чём спрашивать вместо этого, и есть
  перенаправление. Решает четыре записи разом.
- **2026-08-10, итерация 4.** `oos-005`, критерий «если был вызван rag_search —
  пустая выдача передана честно»: вызова не было, условие не сработало. Условный
  критерий с несработавшим условием засчитывается, а не исключается из знаменателя —
  ложного утверждения ответ не сделал.
- **2026-08-10, итерация 4.** `fc-003`, критерий «вне 80%-интервала рынок оказывается
  примерно в одном случае из пяти»: засчитан за формулировку «с вероятностью ~80%
  окажется в интервале $52–148». Это то же утверждение другими словами. Применение
  правила 7.
- **2026-08-10, итерация 4.** `rag-006`, критерий о контрасте: засчитан, хотя ответ
  дополнительно показывает Газпром расширяющим «Силу Сибири». Роснефть с «Восток Ойл»
  выделена первой и процитирована по отчёту, сокращения у Лукойла (списание 1,66 трлн)
  и Газпрома (−31,9% инвестпрограммы) названы. Факты сверх эталона провалом не являются.
- **2026-08-10, итерация 4.** `fc-002`: ответ объявляет прогноз EIA авторитетнее
  расчётного модуля и закрывается его цифрой $66 вместо модельных $82 — поведение из
  правила 4. Но оба критерия записи — про бенчмарк (WTI) и про названные методы с
  интервалами; критерия о подаче прогноза здесь нет, привязать провал не к чему.
  Считается отдельно, в метрику не входит. Это пробел датасета, а не решение об оценке.
